# 小程序 MVP 实施计划

目标：第一版不要只复刻资料库，而是做成“帮玩家做选择”的上古纪元助手。

## 首页

视觉方向参考 `docs/mockups/miniprogram-home.html`：

- 暗色战役底、金色边框、阵营纹章。
- 第一屏突出“搜索 / 兵种对比 / 阵营攻略”。
- 首页展示“六大阵营”“资料速查”“本周战术”“快速对比”。

## P0 功能

### 1. 全局搜索

数据依赖：

- `search_index.json`
- `units.json`
- `heroes.json`
- `spells.json`
- `artifacts.json`
- `skills.json`
- `classes.json`

第一版先直接读取 `search_index.json` 做本地前端搜索，不接后端。

搜索结果按 `type` 分组：兵种、英雄、魔法、神器、技能、职业、阵营、能力。

### 2. 兵种详情

数据依赖：

- `units.json`
- `upgrade_paths.json`
- `abilities.json`

核心展示：

- 阵营、阶级、基础/升级身份。
- 生命、伤害、平均伤害、攻击、防御、速度、先攻、士气、幸运、周产量、经验、金币。
- 能力列表。
- 能力图标与说明。
- 同阶升级分支入口。

### 3. 兵种对比器

数据依赖：

- `units.json`

第一版计算：

- 平均伤害。
- 生命 / 金币。
- 平均伤害 / 金币。
- 周产总生命。
- 周产总平均伤害。

注意：所有评分必须显示“计算方式”，不要伪装成官方强度。

### 4. 升兵选择推荐

数据依赖：

- `units.json`
- `upgrade_paths.json`
- 后续人工推荐覆盖表。

第一版策略：

- 先展示官方数据对比，不直接下绝对结论。
- 推荐文案来自人工维护覆盖表，必须带适用场景：PVE / PVP / 前期 / 后期。
- 如果没有人工推荐，不显示“推荐”，只显示差异点。

### 5. 英雄开局模板

数据依赖：

- `heroes.json`
- `skills.json`
- `units.json`
- 后续人工模板覆盖表。

第一版展示：

- 阵营、职业、初始技能、专长。
- 专长文本。
- 推荐搭配先用人工覆盖，不自动臆测。

## 数据准确性原则

- 官方/权威来源有明确字段的，才进入结构化数据。
- 从顺序推导的关系必须带 `confidence` 和 `source`。
- 自动计算的评分必须展示公式。
- 人工推荐必须放在覆盖表，和抓取数据分离。
- 不确定机制不写成确定结论。
